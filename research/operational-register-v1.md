# Operational baseline v1 — 2026-11-25

The user agreed to stop broad source discovery and move toward a first static feed using the currently available evidence. This register is an engineering input, not a verified timetable or legal route authorization.

## Scope and evidence

- [operational-register-v1.csv](operational-register-v1.csv): 18 observed API route IDs, 36 direction IDs, 17 available KMZ route pairs. The existing API inventory sums to 639 stop occurrences. IDs and route names join against api-route-inventory.csv, kmz-endpoints.csv, routes.csv and operator-route-comparison-2022.csv. Only six explicit route code prefixes are marked confirmed from recorded API names. Historical operator groups are not current assignments.
- Seven API routes have 12 published 2024 timetable documents; Villa Caribe is outside the API baseline and has the thirteenth document. No timetable has yet been converted into actual trips in this register. Timetable IDs and day labels link to timetables.csv; current validity and AM/PM ambiguities require checking. Festivos may provisionally supply Sundays, not a verified Sunday service. Hábil alone does not prove Saturday operation. Missing Sunday/holiday schedules remain blank rather than silently inventing departures.
- Ten routes use provisional POT-derived headways. P1 uses 12/16 minutes (historical Pradera 27 and Garzones variants, POT rows 14/15; alternative 5/8 row 2). M1 uses 5/8 (Mogambo 22 row 10; alternative 10/12 row 9). These are explicitly uncertain because present geometries differ. Furatena 9/12 is also uncertain and POT path 313 is only a candidate. Sabanal 150 minutes has no operating window; do not use urban assumptions for it. Airport source describes approximate hourly service from Terminal 07:00–17:30 only; no reverse schedule or day types confirmed.
- Urban estimated services: provisional operating window 05:00–21:00, weekday peak blocks 06:00–09:00 and 16:00–19:00; Saturday and Sunday off-peak only, Colombian public holidays same as Sunday via Python holidays. These values are model assumptions accepted as planning defaults, not observations. Use half-open frequency intervals and avoid duplicate trips at peak boundaries. The end of a frequency window is exclusive, not necessarily a last departure. Apply only to applicable urban fallback services, not PDF schedules or airport/Sabanal. Confirm direction-specific windows before publication.
- Geometry: use existing KMZ as reference, preserve paired direction endpoints and verify orientation; Tambo second line requires reversal. Furatena excluded from generated public service until its shape is validated. Preserve API order as research reference, do not create coordinate-free GTFS stops. Use geographic terminal/timepoint stops, GraphHopper bus-profile running times as estimates and continuous pickup/dropoff only where supported by actual boarding practice and geometry. Do not assume every segment allows flag boarding.
- Agency: historical 2022 groups are retained as evidence only. Assign verified operators individually or combined virtual agency for genuinely shared service, with attribution; do not duplicate frequencies for multiple operators. Current group assignment unresolved.
- Fares: 2024 document prices historical; do not label current. Fares optional for first feed. Source reuse basis remains unresolved: no full third-party timetable transcriptions or copied datasets are committed here. Public release must wait until applicable reuse basis and publication checks are satisfied.
- New SETP/RIO is a separate future network. Do not impose a January 2027 expiry/changeover date without confirmed implementation information.
